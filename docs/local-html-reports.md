# Offline progress and reminder reports

Create one self-contained HTML snapshot of the currently selected local data:

```powershell
applypilot --workspace C:\local-data followup export-html --output-dir C:\local-reports\progress --since 2026-10-01 --until 2026-10-13 --status failed --status submission_uncertain
applypilot --workspace C:\local-data followup export-html --kind progress --output-dir C:\local-reports\submitted --date-field submitted_at --since 2026-10-01
applypilot --workspace C:\local-data followup export-html --kind reminders --output-dir C:\local-reports\due --on 2026-10-13 --bucket overdue
applypilot --workspace C:\local-data followup export-html --kind reminders --output-dir C:\local-reports\interview-reminders --since 2026-10-13 --until 2026-10-16 --status interview_1
```

Progress is the default `--kind`. It creates `job-progress.html` and reuses the
exact same selected rows as [CSV/Markdown progress export](job-progress-export.md),
including UTC date bounds, repeatable application/recruiting status filters,
intentional unknown submission dates and the chosen `--date-field`.

The reminders kind creates `followup-reminders.html` from the existing
[local reminder list](followup-reminders.md). `--on` defines the reference UTC
day for overdue/today/future grouping, and `--bucket` selects a group. Here
`--since` and `--until` filter the **reminder due date**, not the application's
update or submission date; `--date-field` is a progress-only option. Status
filters match the reminder's current application status or recruiting stage.
Reminders with unknown due dates are excluded when date bounds are supplied.
The reference date defines grouping, not a historical state replay.

Both reports calculate statistics only from selected entries and show every
selected row without the reminder CLI's display limit. Unselected rows are not
embedded as hidden data. No-output matches produce an explicit empty report.
Each report shows its filter scope, UTC dates, generation time, status counts
and review tasks or the reminder's next step. A reminder with an unavailable
target stays visibly marked when it otherwise matches the selected scope.

Open the resulting `.html` file directly in a browser. All styling is inside
the file, uses system fonts, and supports narrow windows and browser printing.
There are no scripts, charts libraries, network resources, external links,
forms or update buttons. The report is a static local snapshot; it does not
contact providers, send notifications or mutate reminders/application state.

The exporter reads existing data only, creates no schema or sidecar, and refuses
to overwrite an existing report. Choose a new output directory for another
snapshot. It does not export resumes, answers, human response payloads, raw
errors, action summaries, source message IDs or URL fields. Safe public labels
are reused from the current export projections and every HTML text/attribute
is escaped. The existing CSV formula-prefix protection is retained unchanged.

The examples use a synthetic database and local reminder file. They contain no
real applicant data. The Python module entry is independently callable:

```python
from applypilot.local_report_html import export_report_html

result = export_report_html(
    r"C:\local-data", r"C:\local-reports\snapshot", kind="reminders",
    on="2026-10-13", bucket="today", statuses=["failed"],
)
```
